# HOUSE POLICY: AI crawlers are allowed. Clients want to be findable in LLM
# answers, so answer engines and training crawlers are both permitted by
# default. The named groups below are redundant against `User-agent: *` — they
# exist so the decision is written down rather than inferred, and so it survives
# someone later tightening the wildcard group.
#
# GOTCHA: a crawler with its own named group ignores the `*` group entirely.
# A Disallow added to `*` will NOT apply to any bot named below — add it to
# each group you mean it for.
#
# To opt a client out, swap that bot's `Allow: /` for `Disallow: /`. The
# meaningful split is answer engines (being cited in AI answers) vs training
# crawlers (content used to train models); a client can allow the first and
# refuse the second.
#
# STAGING/PREVIEW: `Disallow: /` here does NOT keep a preview out of search
# results — a blocked URL can still be indexed from external links, and a
# blocked crawler never reads a page-level noindex. Use host access control,
# an X-Robots-Tag header, or meta robots noindex. See the staging indexing
# rule in docs/rules/seo.md.
